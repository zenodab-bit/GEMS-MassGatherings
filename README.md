# GEMS-MassGatherings

Mass gathering events (festivals, concerts, sport, and staged events such as restaurants that feed a football match) on top of the [GEMS](https://github.com/IMMIDD/GEMS) epidemic simulator. You describe the events; the code draws who attends, simulates the epidemic with GEMS, and reports the infections at each event and what the events changed.

## Setup (once per machine)

1. Install Julia 1.12 or newer: https://julialang.org/downloads
2. Get the code:
   ```
   git clone -b multi-event-fixes https://github.com/zenodab-bit/GEMS-MassGatherings.git
   cd GEMS-MassGatherings
   ```
3. Install the exact package versions in `Manifest.toml` (don't run `Pkg.update()` afterwards):
   ```
   julia setup.jl
   ```

## Running a simulation

```
julia -t 8 run.jl
```

`-t 8` uses 8 threads, about twice as fast ([Reproducibility and speed](docs/reproducibility.md)). Results go to `Results/`.

- **`config/user_config.jl`**: the events, transmission, GEMS configuration and seed ([Configuring events](docs/events.md)).
- **`run.jl`**: replicates, validation, the population, and experiments, all off by default ([Experiments](docs/experiments.md)).

## The population

No population is shipped with the code.

- **By default** each run uses a **synthetic population** generated by GEMS (`synthetic = (; n = 100_000)`): good for trying things out, not representative.
- **For realistic results**, set `population_file` to a `.jld2` file with a table under `"data"`: at least `id`, `age`, `sex` (1 or 2) and the GEMS setting ids (`household`, optionally `office`, `schoolclass`, `municipality`). `settings_file` optionally adds its GEMS settings file (slower). Git ignores `.jld2` files in `data/`.
- **To keep your settings out of git**, copy `run.jl` to `my_<something>.jl`; git ignores `my_*.jl`.

## Configuring events

An example; every field is in [Configuring events](docs/events.md):

```julia
festival = Category(
    id = 1, name = "festival",
    date_range = (40, 60),           # the days it can happen on
    n_draws = 1,                     # how often it recurs
    sections = [EventSection(id = 1, name = "standing", n_range = (800, 1000),
                             mean_contacts = 12.0, std_contacts = 18.0)],
    min_age = 18,
    core = 0.0, loyalty = 0.0,       # returning attendees across draws
)

football = StagedCategory(           # stages on the same day, people can attend several
    id = 2, name = "football",
    date_range = (20, 50), n_draws = 2,
    stages = [
        Stage(name = "match", venues = [Venue(name = "stadium", n_range = (20000, 25000), mean_contacts = 10.0, std_contacts = 15.0)]),
        Stage(name = "restaurants", overlap = 0.3,   # 30% of their guests come from the match
              venues = [Venue(name = "restaurant$i", n_range = (40, 80), mean_contacts = 4.0, std_contacts = 6.0) for i in 1:10]),
    ],
)
```

## What you get

Each run writes `Results/run_<n>sims_<date and time>/`:

| File | Content |
|---|---|
| `multievent_analysis.txt` | Global metrics, and per event the attendees' states and infections, over all replicates |
| `*.png`, `infected_by_section/`, `seir/` | Epidemic curves, cases by setting, infections per event, per section or venue, and each event's states |
| `events.csv`, `event_results.csv`, `attendance.jld2` | The events, per-replicate results, who attended what |
| `validation.txt` | The checks of the run |
| `run_info/` | What's needed to repeat the run |

Details: [How it works](docs/how_it_works.md#what-a-run-folder-contains).

## Checking the code

After changing the code, run the quick test (about 2 minutes):

```
julia -t 8 test/test.jl
```

## Project layout

```
run.jl                 the script to run
config/                user_config.jl and the GEMS configuration (TOML)
src/                   the MassGatherings package
test/test.jl           the quick test
data/                  your population files (not in git)
docs/                  the documentation
Results/               the results (not in git)
```
